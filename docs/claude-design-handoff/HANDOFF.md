## 3. 現在の問題 — 症状 → 原因 → 該当ファイル

Humanから挙がった10点の指摘を、実コードの該当値まで特定した。
**ここがこの引き継ぎの中核。** ムードボードではなく、直す場所が特定済みの仕様書として扱ってほしい。

### 3-1. 「文字が全体的に小さい」

| 箇所 | 現在値 | ファイル |
|---|---|---|
| セクションのリード文 | `text-[14.5px] sm:text-[15.5px]` | `src/components/ui/Section.tsx` |
| セクション大見出し | `text-[27px] sm:text-[34px]` | `src/components/ui/Section.tsx` |
| eyebrow | `text-[11.5px]` | `src/components/ui/Section.tsx` |
| 本文（Problem） | `text-[14px]` | `ProblemSection.tsx` |
| 本文（HowItWorks / Screens / Feature小カード / UseCase / FAQ回答） | `text-[13.5px]` | 各セクション |
| 補足・注記 | `text-[12.5px]` / `text-[12px]` | 各セクション |
| Pricing表 セル | `text-[13.5px]` | `PricingSection.tsx` |
| Pricing表 ヘッダー | `text-[12px]` | `PricingSection.tsx` |

> **`src/components/ui/Section.tsx` は全セクションの見出し階層を1か所で決めている。**
> ここを直すと、大見出し・リード文・eyebrowの大きさが**LP全体で同時に**直る。最優先で見るべきファイル。

日本語は同じpx値でもラテン文字より小さく見える。13.5pxの日本語本文は、
プロダクトサイトの標準（15〜16px相当）から見ると明確に小さい。

### 3-2. 「本文色が薄く読みにくい」

実測のコントラスト比（WCAG 2.1）：

| token | 値 | 白地 | 淡ティール地 `#E4F4EF` | 判定 |
|---|---|---|---|---|
| `--color-text` | `#16211F` | 16.52:1 | 14.54:1 | ✅ |
| `--color-body` | `#5B6764` | 5.88:1 | 5.18:1 | ✅ AA（**色は合格。小ささが主因**） |
| `--color-muted` | `#7E8986` | 3.61:1 | 3.18:1 | ❌ 通常サイズでAA未達 |
| `--color-faint` | `#939E9B` | 2.76:1 | 2.43:1 | ❌ |
| `--color-faint2` | `#A6AEAB` | 2.27:1 | 2.00:1 | ❌ **最も薄い。Pricing表の「—」がこれ** |
| `--color-brand` | `#0E9488` | 3.74:1 | 3.30:1 | ❌ 通常サイズでAA未達（**リンク色に使われている**） |

**重要な発見**: 本文 `--color-body` は実はAA合格している。
「薄い」という体感の主因は**色ではなくサイズと行間**。
一方で `muted` / `faint2` / `brand`（リンク）は**本当に**基準未達なので、こちらは色も直す必要がある。

→ 対処の優先順位は **① サイズを上げる → ② `muted`/`faint2`/`brand` の使用箇所を締める**。
`--color-body` を闇雲に濃くすると、アプリ側tokenとの整合が崩れる（§5-2参照）。

### 3-3. 「薄緑背景＋白カード＋薄い文字が同化している」

最も同化しているのは **FeatureSection**：

- 地: `.ground-mint` = `linear-gradient(180deg, #E4F4EF 0%, #F2FBF8 45%, #FFFFFF 100%)`
- その上の小カード: `bg-white` + `border-line`（`#ECEFED`）
- カード内本文: `text-[13.5px] text-body`

`#FFFFFF` のカードを `#F2FBF8`〜`#FFFFFF` の地に置き、境界線が `#ECEFED`
（**白とのコントラスト比 1.16:1**／地色 `#F2FBF8` に対しては **1.10:1**）。
**セクション下半分ではカードの輪郭が事実上消える。**
`screenshots/desktop-05-features.png` で確認できる。

同じ問題は Pricing の「Proが要るのは、こんなときだけ」カード（`bg-screen #F4F6F5` on 白地）にもある。

### 3-4. 「カード同士の視覚的階層が弱い」

FeatureSectionは意図的に非対称グリッド（主役2枚が大、小カード6枚）にしているが、
小カード6枚が完全に等価（同じ余白・同じ文字サイズ・同じ境界線）。
影は主役カードの `shadow-[0_18px_40px_-30px_rgba(16,33,31,0.5)]` のみで、
小カードには影がない。結果、主役と小カードの差が「大きさ」だけで表現されている。

### 3-5. 「中盤以降の情報密度が均一」「視線が止まる場所が少ない」

`screenshots/desktop-00-fullpage.png`（ページ全体・1440×9540）を見ると一目瞭然：
Hero（暗）と ScreensSection（暗）には視線の停留点があるが、
**Features → UseCase → Pricing → FAQ の 4,466px（y=4144〜8610・全体の47%）が、
明るい地に小さい文字が均一に並ぶ帯**になっている。
**ページのほぼ半分**に「大きい数字」「強い対比」「余白の緩急」がほぼない。

唯一の大きな要素は Pricing の `¥0` / `¥500`（`text-[40px]`）。

### 3-6. 「Hero以外のセクションで印象が弱い」

各セクションの見出しがすべて同じ `text-[27px] sm:text-[34px]`（`Section.tsx`）で、
セクション間に強弱がない。Heroの `text-[31px] sm:text-[44px] lg:text-[52px]` だけが突出している。

### 3-7. 「Pricing表の文字も小さい」「FAQの可読性が弱い」

- Pricing表: セル `13.5px` / ヘッダー `12px` / `min-w-[440px]` + `overflow-x-auto`
  → **本文サイズを上げると横スクロールが発生する。** §6-4の指示に従うこと。
- FAQ: 質問 `15px` / 回答 `13.5px` / 区切りは `divide-line`（`#ECEFED`）のみ。
  11問が等間隔で並び、開閉状態の視覚差も `＋` の回転だけ。

## 4. 色の方針 — ティール主体を崩さず、コーラルを少量

### 4-1. 現在の色

- **メイン**: ティール `#0E9488`（`--color-brand`）— CTA・主役・購入済み
- **補助**: アンバー `#E0A53B` 系（`--color-candidate`）— 「候補＝まだ買うか決めていない」
- **Pro**: ゴールド `#B5731A` / グラデ `#EBC976→#D9A441` — バッジ・識別のみ
- **暗面**: `#11201E` / `#16211F`

### 4-2. ⚠️ DECISION REQUIRED — コーラル追加は「どう入れるか」を先に決める必要がある

Humanの希望は「ティールと強く対比するコーラル系を1色、視線誘導に少量だけ足す」
（想定 `#E76F51` 前後、soft背景 `#FCE9E3` 前後）。

**ただし、単純に足すと2つの問題が起きる。Claude Designは以下を知らずに判断できない。**

**問題A: LPには既に第2アクセント（アンバー）があり、意味を持っている。**
アンバーは本体アプリで「候補＝まだ買うか決めていない状態」を指す色で、
LPでも意味が通る場所だけに使われている：

- `ProblemSection`（迷っている場面）の番号・上罫・`.ground-warm` 地
- `UseCaseSection` のタグ
- `FeatureSection` のカテゴリーカード
- `FAQSection` の `.ground-warm` 地

ここへコーラルを足すと **ティール＋アンバー＋コーラルの3アクセント**になり、
視線誘導は**弱くなる**（強調色が3つあると、どれも強調にならない）。

**問題B: 本体アプリは既にコーラル系を持っているが、意味は「破壊的操作」。**

`travel-rate-camera-app/src/theme/tokens.ts`:

```
danger:       '#C2543F'   ← 削除・破壊的操作
dangerAlt:    '#D9614E'   ← Humanの希望 #E76F51 に非常に近い
dangerSoft:   '#FBF3F1'
sundayRed:    '#C2543F'   ← カレンダーの日曜
```

つまりコーラル≒赤系は、アプリ内では**「消す」の色**。
LPで「Proへの視線誘導」にこの色域を使うと、アプリを触った後のユーザーには意味がねじれる。

#### 選択肢（Humanが決めること）

| 案 | 内容 | 評価 |
|---|---|---|
| **A** | コーラルが**アンバーのLPでの役割を置き換える**（アンバーは端末モック内＝アプリ画面だけに残す） | アクセントは2つのまま。対比は最も強い。ただしLP地色（`.ground-warm`）の意味づけを作り直す必要がある |
| **B** | コーラルが**アンバーに加わる**（3アクセント） | Humanの原文に最も近いが、視線誘導はかえって弱まる懸念 |
| **C ⭐推奨** | **アンバーは「候補」意味のある場所だけに退く／コーラルはLP専用の注意喚起色として少量** | アンバーの意味（アプリ整合）を守りつつ、対比色を1つ得る。下に具体ルールを書く |

#### C案の具体ルール（この引き継ぎの既定の前提として書いてある）

- **アンバーを残す場所**: 端末モック内（アプリ実装そのもの・変更禁止）、
  `FeatureSection` のカテゴリーカード（「候補として保存」の文脈）
- **アンバーを退かせてよい場所**: `.ground-warm` のセクション地（Problem / FAQ）、
  `UseCaseSection` のタグ、`ProblemSection` の番号・罫
- **コーラルを使ってよい場所**（少量・面積で主役にしない）
  ⚠️ **用途によって使える明度が違う。実測に基づく区別なので必ず守ること**:

  | 用途 | 使う値 | 理由 |
  |---|---|---|
  | **文字が絡まない**視線誘導 — 罫・ドット・アイコン・下線・図形・小さな面 | `#E76F51` | 文字の可読性に依存しない |
  | **文字が絡む**強調 — 強調語・数字・badgeの文字・Proラベル | **`#C2543F` 相当まで暗いコーラル** | `#E76F51` は白地 **3.09:1**、白文字を載せても **3.09:1** で**どちらも不可**。`#C2543F` なら双方向 4.53:1 |

  - Proへの視線誘導は **罫・小さな面**で行い、文字に色を付けたい場合のみ `#C2543F` 相当を使う
  - もう一つの安全な型: **コーラルは面に使わず、`--color-text` の文字＋コーラルの罫**で組む
- **コーラルを使ってはいけない場所**:
  - 主要CTAそのもの（**CTAは必ずティールのまま**。Header・Hero・最終CTA）
  - 端末モック（`PhoneFrame`）の内側 — **アプリ実装であり変更禁止**
  - 「削除」「エラー」「警告」と誤読される文脈
  - 面積の大きい背景（主役色にしない）

**HEX値は絶対値ではない。** `#E76F51` / `#FCE9E3` は方向性の例示。
ティールと対比し、安っぽくならず、`danger #C2543F` とは明確に区別がつく、
少しくすんだコーラルであれば調整してよい。

⚠️ **もう1点、実測で判明した重要な制約**:
ティール `#0E9488` とコーラル `#E76F51` は**輝度がほぼ同じ（相互コントラスト 1.21:1）**。
色相では強く対比するが、**明度差がほぼ無い**。
→ グレースケール印刷・1型/2型色覚・低照度画面では**この2色が判別できない**。
　 コーラルを使う箇所には、**色以外の手がかり（サイズ・位置・形・罫の太さ）を必ず併用すること。**
　 「ティールCTAの隣にコーラルのアクセント」を明度差なしで置くと、
　 一部のユーザーにはのっぺりした一色の塊に見える。

> **Humanへ**: この A/B/C はClaude Designを走らせる前に決めてください。
> 決めずに投げると、Claude Designは3アクセント（案B）を選びがちです。

## 6. Claude Designが知らないと必ず踏む罠

### 6-1. このLPに画像ファイルは1枚も無い

`public/` にあるのはNext.jsの初期SVGだけで、LPからは参照していない。
**端末モックの中身はすべてCSS/JSXで実装された「実画面の再現」**（`src/components/mock/screens/*`）。
スクリーンショット画像ではない。だから「画像を差し替える」提案は成立しない。

OGP画像も `src/app/opengraph-image.tsx` がコードで生成している。

### 6-2. 端末モック（PhoneFrame）の内側は凍結領域

`PhoneFrame` は **iPhone論理解像度 393×852pt で実装**され、`--s`（CSS変数）で拡縮する。
中の画面はアプリのハンドオフ仕様のpx値をそのまま使っている。

- **フレームの外側**（配置・大きさ `--s`・背後のglow・キャプション・並べ方）は変更してよい
- **フレームの内側**は変更禁止

そのため、**`src/components/mock/screens/*` と `src/components/mock/chrome.tsx` は
この引き継ぎパッケージにあえて同梱していない**（約1,000行のアプリUI内部実装）。
同梱すると「ここも直せる」と誤解されるため。凍結領域として扱うこと。

### 6-3. `LINKS.appStore === null` による条件分岐を壊さないこと

App Store URLが未確定のため、`Header` / `HeroSection` / `CTASection` の3か所に
**三項分岐**がある：

```tsx
{LINKS.appStore ? (
  <a href={LINKS.appStore}>App Storeで入手</a>
) : (
  <a href={LINKS.contact}>公開のお知らせを受け取る →</a>
)}
```

公開が決まったら `appSpec.ts` の1行を変えるだけで切り替わる設計。
**「App Storeボタン1つ」に単純化するのは視覚的な簡略化に見えて、機能の後退。**
両方の分岐をそのまま残し、両方の状態でデザインが成立すること。

### 6-4. 本文を大きくすると Pricing表が横スクロールする

現在 `min-w-[440px]` + `overflow-x-auto`。文字を大きくすると390px幅で必ず溢れる。
→ **モバイルでは表をやめ、プラン別カード（無料版カード／Proカード）に組み替えること。**
　　ただし**行の内容・順序・文言はそのまま**。desktopは表のままでよい。

### 6-5. 日本語フォントの都合

```css
font-family: "Hiragino Kaku Gothic ProN", "Hiragino Sans", "Yu Gothic", "Meiryo",
             system-ui, -apple-system, Arial, sans-serif;
```

- 日本語ゴシックは**ウェイトが実質2段階**（normal / bold）。
  `font-semibold`(600) と `font-bold`(700) の差はWindows実機でほぼ出ない。
  → **階層をウェイトだけで作らない。サイズ・色・余白で作ること。**
- 日本語は字面が大きく、`letter-spacing` を詰めすぎると潰れる。
  現在 `tracking-[-0.02em]`〜`tracking-[-0.03em]` が見出しに入っている。
- 行間は現在 `leading-[1.9]`〜`leading-[1.95]`。日本語としては妥当なので、
  サイズを上げる際も 1.8 を下回らないこと。
- `.tabular`（`font-variant-numeric: tabular-nums`）は金額に必ず付いている。外さないこと。

### 6-6. 数値・文言の多くは `appSpec.ts` から補間されている

例：

```tsx
1つの旅行につき{FREE_LIMITS.savesPerTrip}件まで保存できます   → 「10件」
¥{PRICING.monthlyYen.toLocaleString("ja-JP")}                 → 「¥500」
```

**これらを直値（ハードコード）に書き換えないこと。** 詳細は `LOCKED_CONTENT.md`。

### 6-7. アクセシビリティ・実装上の約束

- `prefers-reduced-motion: reduce` で `.scan-line` / `.rise` / smooth scroll を無効化済み。
  アニメーションを足す場合も同じガードを付けること。
- `PhoneFrame` は `role="img"` + `aria-label` で画面内容を説明している。ラベルを消さない。
- 各セクションの `id`（`#howto` `#screens` `#features` `#pricing` `#faq` `#cta`）と
  `scroll-mt-16` はヘッダー分のオフセット。**id・scroll-mt を消さない**（ナビが飛ばなくなる）。
- ヘッダー/フッターのページ内リンクは必ず `/#id` 形式（`#id` だと下層ページで壊れる）。

## 8. 目指す質感

- **teal main, coral complementary accent**（§4-2の決定に従う）
- **stronger typography** / **better contrast** / **bigger body text**
- **stronger visual hierarchy**
- 薄緑地＋白カード＋薄文字の同化を解消する
- premium but practical — 旅行アプリ。実用品であって高級品ではない
- desktop / mobile 両方で成立すること（mobileは390px基準）

**避けたい方向**:

- ネオン／蛍光
- 過度にplayful、ポップすぎる
- 汎用SaaSテンプレート感
- 過剰なglassmorphism
- 紫グラデーションの「AI製品」ルック
