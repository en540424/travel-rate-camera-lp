## これは何か

「旅レートカメラ」— 海外旅行の買い物で、値札にカメラをかざすと日本円の目安が出るiPhoneアプリ。
レートはユーザーが自分で入力し、換算は端末内で完結します（自動取得はしません）。
まだApp Store未公開で、LPの主CTAは「公開のお知らせを受け取る」です。
技術構成は Next.js 16 App Router / React 19 / TypeScript / Tailwind CSS v4。日本語のみ。

## 絶対条件（守れていない案は採用できません）

- **各セクションの意味を変えない**

## 改善してほしいこと

現状は「骨格は正しいが、仕上げが足りない」状態です。具体的な指摘：

1. 文字が全体的に小さい（本文の多くが **13.5px**。日本語としてプロダクトサイトの標準より明確に小さい）
2. 補助テキストが薄い（`#7E8986` は白地3.61:1、`#A6AEAB` は2.27:1 でWCAG AA未達）
3. **薄緑の地（`#E4F4EF`→白）に白カードを置き、罫が `#ECEFED` なので輪郭が消えている**（Featuresセクション）
4. カード同士の視覚的階層が弱い（小カード6枚が完全に等価。影も無い）
5. 中盤以降（Features→UseCase→Pricing→FAQ）の情報密度が均一で、視線が止まる場所が無い
6. Hero以外のセクションで印象が弱い（全セクションの見出しが同じ 27/34px）
7. Pricing表の文字が小さい（セル13.5px、`—` が読めない）
8. FAQの可読性が弱い（11問が等間隔で塊に見える）

改善対象は **layout / hierarchy / card / CTA / typography / spacing / contrast / background /
color balance / mobile・desktop両方の仕上げ**。

### 特に効くポイント

- **`src/components/ui/Section.tsx` が全セクションの見出し階層を1か所で決めています。**
  ここを直すと、大見出し・リード文・eyebrowがLP全体で同時に直ります。最優先で見てください
- **中盤（Features / UseCase / Pricing / FAQ）に「視線が止まる大きな要素」を作ること。**
  ただし情報は足さず、**既にある要素を大きく・強くする**ことで実現してください
- **`--color-body` `#5B6764` は実はAA合格（5.88:1）です。** 「薄い」体感の主因は色ではなく
  **サイズと行間**。闇雲に濃くせず、まずサイズを上げてください

## 【色の方針】

メインは**ティール `#0E9488`**。このブランド軸は維持してください。
対比色として**コーラル系を少量**足したい、というのが方針です。

ただし注意点が2つあります：

- このLPには既に第2アクセントとして**アンバー `#E0A53B`** があり、
  アプリ側で「候補＝まだ買うか決めていない」という**意味**を持っています
- アプリ側ではコーラル/赤系（`#C2543F` / `#D9614E`）は**「削除」の色**です

そこで次の方針でお願いします（案C）：

- **アンバーは「候補」の意味がある場所だけに退く**
  （端末モック内、Featuresのカテゴリーカード）
- **コーラルはLP専用の視線誘導色として、少量だけ**使う
  - 使ってよい: 強調語・数字、Proへの視線誘導（バッジ・罫・小さな面）、
    小さなbadge、セクションアクセント、CTA周辺の補助要素
  - **使ってはいけない: 主要CTAそのもの（CTAは必ずティール）**、端末モックの内側、
    「削除/エラー/警告」と誤読される文脈、面積の大きい背景
- **コーラルを主役色にしない**

想定値は `#E76F51` 前後、淡い面は `#FCE9E3` 前後。**ただしこのHEXは絶対値ではありません。**
ティールと対比し、安っぽくならず、少しくすんだコーラルであれば調整可です。

### コーラルを使うときの実測上の制約（重要）

- `#E76F51` は白地で **3.09:1**、白文字を載せても **3.09:1**。
  → **文字色にも、白文字を載せる背景にも使えません。**
  　 使えるのは罫・ドット・アイコン・下線・小さな図形など、文字の可読性に依存しない用途
- 文字が絡む強調には `#C2543F` 相当（白地4.53:1）まで暗くする必要があります
- ⚠️ **ティール `#0E9488` とコーラル `#E76F51` は輝度がほぼ同じ（相互1.21:1）。**
  色相では強く対比しますが**明度差がほぼ無い**ため、グレースケールや色覚特性によっては
  区別できません。**色以外の手がかり（サイズ・位置・形・罫の太さ）を必ず併用してください**

## 実装上、知らないと必ず踏む罠

- **App Store URLが未確定**のため、Header / Hero / 最終CTA の3か所に
  `LINKS.appStore ? "App Storeで入手" : "公開のお知らせを受け取る"` という**条件分岐**があります。
  **「App Storeボタン1つ」に単純化しないでください。**両方の状態でデザインが成立すること
- **本文を大きくすると Pricing表（`min-w-[440px]`）が390px幅で溢れます。**
  → モバイルでは表をやめ、**プラン別カード**に組み替えてください（行の内容・順序・文言はそのまま）
- **日本語フォント**（Hiragino / Yu Gothic / Meiryo）は**実質2ウェイト**。
  `font-semibold` と `font-bold` の差はほぼ出ません。
  → **階層をウェイトだけで作らず、サイズ・色・余白で作ってください**
- 行間は現在 1.9〜1.95。日本語として妥当なので、**1.8を下回らないこと**
- 金額の `font-variant-numeric: tabular-nums` を外さないこと
- セクションの `id`（`#howto` `#screens` `#features` `#pricing` `#faq` `#cta`）と
  `scroll-mt-16` を消さないこと（ヘッダー分のオフセット。消すとナビが飛ばなくなる）
- ページ内リンクは `/#id` 形式（`#id` だと下層ページで壊れる）
- `prefers-reduced-motion: reduce` のガードが既にあります。アニメを足す場合も同じガードを付けること

## Humanの操作手順

1. `HANDOFF.md` §4-2 の A / B / C を決める（推奨: C。上のプロンプトは C で書いてある）
2. Claude Design を開く
3. ZIP（`travel-rate-camera-lp-claude-design-handoff.zip`）を展開して添付、
   またはZIPのままアップロード
4. 上の「▼ここから下をコピー▼ 〜 ▲ここまで▲」を貼って送信
5. 出てきた案を確認。**文言が変わっていないか / 端末モックの中身が変わっていないか**を最初に見る
6. 問題なければ、Claude Code へ戻して実装（branch `feat/lp-v2-visual-rebuild` 上）

## Claude Designの結果をClaude Codeへ戻す方法

Claude Design から受け取るもののうち、**実装に必要なのは次の3つ**です：

1. **デザイン画像**（desktop / mobile、全セクション）
2. **使った色の値一覧**（HEX）
3. **変更の意図**（どのセクションで何をどう変えたか・なぜ）

Claude Code のセッションで、次のように伝えてください：

```
Claude Designでvisual polish案ができた。
docs/claude-design-handoff/ の HANDOFF.md / LOCKED_CONTENT.md の制約を守ったまま、
この案を feat/lp-v2-visual-rebuild 上で実装して。

[デザイン画像を添付]
[色の値一覧を貼る]
[変更意図を貼る]

実装後に npx tsc --noEmit / npm run lint / npm run build を通すこと。
masterへのmerge・push・Vercel反映はしない。
```

実装時、Claude Code側は必ず `LOCKED_CONTENT.md` と照合して
**文言が1文字も変わっていないこと**を確認してからcommitします。
